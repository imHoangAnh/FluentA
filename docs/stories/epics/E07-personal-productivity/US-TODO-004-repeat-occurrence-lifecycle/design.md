# Design

## Vertical Slice

Extend the existing Todo aggregate and additive Todo DTO shape with nullable
`repeatPattern`. The accepted API values are exactly `Daily`, `Weekdays`,
`Weekly`, `Monthly`, and `Yearly`; `null` means the optional repeat field is
disabled. Keep the existing `/api/v1/todos` POST/PATCH/list/delete routes.

Persist recurrence on `todo_items` with nullable `repeat_pattern`, nullable
`generated_from_todo_id`, and non-null
`is_generated_occurrence_pristine`. Store the enum as a bounded string. A
filtered unique index on active, non-null `generated_from_todo_id` permits at
most one live child for a source while still allowing a pristine child to be
soft-deleted and regenerated after a later completion.

## Date Rules

The domain owns one deterministic next-date function:

- Daily adds one calendar day.
- Weekdays advances to the next Monday-Friday date, skipping Saturday and
  Sunday.
- Weekly adds seven calendar days.
- Monthly advances one month and clamps the source day to the last valid day of
  the target month.
- Yearly advances one year and clamps 29 February to 28 February when the
  target year is not a leap year.

The generated occurrence copies title, note, importance, repeat, and later the
reminder fields added by `US-TODO-005`. It receives a new identity, the next
date, the next available order on that date, and starts incomplete.

## Atomic Lifecycle

The Todo repository owns one completion-lifecycle transaction. It locks the
owner-scoped source row before deciding whether a live generated child already
exists.

- Completing a non-recurring item only updates completion state.
- Completing a recurring item creates one child when none exists. The filtered
  unique index is the final concurrency guard against duplicate children.
- Repeating the same completion request is idempotent.
- Reopening finds the active child generated from that source. A pristine child
  is soft-deleted in the same transaction. A non-pristine child remains and the
  response includes `warningCode: recurrence-next-retained`.
- Deleting any item remains the current owner-scoped soft delete and never
  traverses lineage.

Any direct user PATCH that materially changes an autogenerated child marks it
non-pristine. System creation does not. Timestamp comparison is not used.

## Frontend Interaction

Add one Repeat row to the shared Todo detail panel. Its menu shows exactly the
five approved choices plus the empty `Does not repeat` state needed to clear an
optional field. Selecting a value sends one field-scoped PATCH and keeps the
panel open. The selected state reads from the returned task, and an edited-child
reopen warning is shown through the existing page feedback seam.

No repeat text or icon is added to compact My Day or interim Week rows.

## Compatibility And Stop Conditions

- No existing route, envelope, ownership filter, completion timestamp,
  ordering, soft-delete, or SignalR event is removed.
- The DTO change is additive. Existing tasks migrate to `repeat_pattern = null`
  and `is_generated_occurrence_pristine = false`.
- Stop if the implementation requires custom recurrence, series editing,
  cascading delete, a second recurrence table, or a new public route.
- Stop if row-locking plus the unique active-child index cannot make completion
  and child generation one PostgreSQL transaction.
